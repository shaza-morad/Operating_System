Basic Concepts of CPU Scheduling

المفاهيم الأساسية لجدولة المعالج

⚡ CPU-I/O Burst Cycle دورة اندفاع المعالج والإدخال/الإخراج

Process Execution تنفيذ العمليات

Process execution consists of a cycle of CPU execution and I/O wait. Processes alternate back and forth between these two states:

تنفيذ أي عملية يتكون من دورة متتابعة من تشغيل المعالج وانتظار الإدخال/الإخراج. تتناوب العمليات بين الحالتين:

  • CPU Burst: The process is executing instructions on the processor.
  • I/O Burst: The process is blocked waiting for an I/O operation (disk, network, user input).
  • Histogram of CPU Bursts: Empirical distributions reveal an exponential or hyperexponential curve—a large frequency of short bursts (I/O-bound jobs) and a small frequency of very long bursts (CPU-bound jobs).
  • اندفاع المعالج (CPU Burst): تنفيذ التعليمات الحسابية والمنطقية على المعالج.
  • اندفاع الإدخال/الإخراج (I/O Burst): توقف العملية لانتظار عمليات القراءة والكتابة والشبكة.
  • منحنى توزيع أزمنة المعالج: تُظهر الأنظمة منحنى أسياً يتميز بـ تردد عالٍ جداً لفترات اندفاع قصيرة (عمليات I/O-bound) و تردد منخفض لفترات طويلة (عمليات CPU-bound).

🎯 Scheduler vs. Dispatcher المجدول مقابل الموزع (Dispatcher)

Core Roles الأدوار الأساسية

A vital distinction heavily tested on exams:

فارق جوهري وأساسي يتكرر دوماً في الامتحانات:

  • CPU Scheduler (Short-Term Scheduler): Selects a process from the ready queue and decides who gets the CPU next.
  • Dispatcher: The module that actually gives physical control of the CPU to the selected process. Its 3 core duties:
    1. Switching context (saving/restoring registers).
    2. Switching to user mode.
    3. Jumping to the proper location in the user program to restart it.
  • Dispatch Latency: The time it takes for the dispatcher to stop one process and start another running. Must be minimized!
  • مجدول المعالج (Short-Term Scheduler): يختار العملية الأنسب من طابور الجاهزية (Ready Queue) ويحدد من سيحصل على المعالج.
  • الموزع (Dispatcher): الوحدة البرمجية المسؤولة عن تسليم السيطرة الفعلية على المعالج للعملية المختارة، ويقوم بثلاث مهام:
    1. تبديل السياق (حفظ واسترجاع المسجلات).
    2. التحويل إلى وضع المستخدم (User Mode).
    3. القفز إلى العنوان المناسب في برنامج المستخدم لاستئنافه.
  • زمن تأخير التوزيع (Dispatch Latency): الوقت المستغرق لإيقاف عملية وبدء تشغيل العملية الأخرى. يجب تقليله إلى أدنى حد!
Crucial Exam Concept Preemptive vs. Nonpreemptive (Cooperative) Scheduling الجدولة الاستباقية مقابل غير الاستباقية (التعاونية)

CPU scheduling decisions take place under exactly 4 circumstances:

تُتخذ قرارات جدولة المعالج تحت أربعة ظروف محددة تماماً:

1

Switches from Running → Waiting state

التحول من حالة التشغيل إلى الانتظار (Running → Waiting)

E.g., I/O request initiated, or calling wait() for child process completion. Nonpreemptive.

مثل طلب قراءة/كتابة (I/O) أو استدعاء wait() لانتظار عملية فرعية. غير استباقية (إجبارية).

2

Switches from Running → Ready state

التحول من حالة التشغيل إلى الجاهزية (Running → Ready)

E.g., timer interrupt expires or a higher-priority process arrives. Preemptive.

مثل انتهاء الشريحة الزمنية (Timer Interrupt) أو وصول عملية ذات أولوية أعلى. استباقية.

3

Switches from Waiting → Ready state

التحول من حالة الانتظار إلى الجاهزية (Waiting → Ready)

E.g., completion of an I/O operation. The newly ready job may preempt the current CPU occupant. Preemptive.

مثل اكتمال عملية الإدخال/الإخراج وانتقال العملية إلى Ready. قد تقطع العملية المنفذة حالياً. استباقية.

4

Terminates

إنهاء العملية (Terminates)

The process exits normally or abnormally; the CPU is freed. Nonpreemptive.

تنتهي العملية تلقائياً أو بخطأ، فيصبح المعالج حراً بالضرورة. غير استباقية (إجبارية).

Rule: Scheduling under circumstances 1 and 4 is strictly nonpreemptive (the running process yields the CPU voluntarily). Under 2 and 3, scheduling is preemptive (requires handling shared kernel data structures and interrupts carefully).

القاعدة الامتحانية: الجدولة تحت الحالتين 1 و 4 تكون غير استباقية حتماً (العملية تتنازل عن المعالج باختيارها أو بموتها). بينما تحت الحالتين 2 و 3 تكون الجدولة استباقية (تتطلب حماية البيانات المشتركة في الـ Kernel لمنع حالات السباق).

Core Scheduling Algorithms Analyzed

تحليل خوارزميات الجدولة الأساسية

1️⃣ FCFS (First-Come, First-Served)

Nonpreemptive غير استباقية FIFO Queue طابور FIFO

The simplest CPU-scheduling algorithm: the process that requests the CPU first is allocated the CPU first using a standard FIFO queue.

أبسط خوارزميات الجدولة: العملية التي تطلب المعالج أولاً تحصل عليه أولاً باستخدام طابور FIFO عادي.

  • Average Waiting Time: Highly variable and sensitive to the arrival order of processes.
  • The Convoy Effect: Occurs when one large CPU-bound process holds the CPU while numerous short I/O-bound processes sit idle in the ready queue waiting for it. Leads to severely degraded CPU and I/O device utilization!
  • Starvation: Impossible in FCFS because every process in the FIFO queue will eventually execute.
  • متوسط زمن الانتظار: غير مستقر ويتغير بشدة حسب ترتيب وصول العمليات.
  • تأثير القافلة (Convoy Effect): يحدث عندما تستحوذ عملية طويلة ومستهلكة للمعالج على الـ CPU، بينما تقف خلفها عمليات قصيرة معطلة بانتظارها، مما يخفض كفاءة استغلال الأجهزة والمعالج.
  • المجاعة (Starvation): لا تحدث إطلاقاً في FCFS لأن كل عملية ستصل إلى مقدمة الطابور حتماً.

2️⃣ SJF & SRTF (Shortest Job First)

Optimal Waiting Time أفضل وقت انتظار Preemptive/Nonpreemptive استباقية أو غير استباقية

Associates with each process the length of its next CPU burst. The CPU is allocated to the process with the shortest burst.

تربط كل عملية بطول فترة اندفاع المعالج التالية لها، ويتم تخصيص المعالج للعملية ذات الفترة الأقصر.

  • Optimality: Provably optimal—gives the minimum average waiting time for any given set of stationary processes.
  • Difficulty: Knowing the length of the next CPU burst in advance is practically impossible in general OS.
  • Preemptive SJF (SRTF): Shortest-Remaining-Time-First. If a new process arrives with a remaining CPU burst shorter than the currently running process, the current process is preempted!
  • Major Problem: Starvation (Indefinite blocking) for long processes if short processes continuously enter the ready queue.
  • المثالية الرياضية: خوارزمية مثالية مثبتة رياضياً—تعطي أقل متوسط زمن انتظار لأي مجموعة من العمليات.
  • الصعوبة العملية: استحالة معرفة مدة تشغيل المعالج القادمة مسبقاً بدقة في أنظمة التشغيل العامة.
  • الـ SJF الاستباقي (SRTF): تسمى أقصر وقت متبقٍ أولاً. إذا وصلت عملية جديدة بوقت متبقٍ أقل من العملية الشغالة حالياً، يتم قطعها فوراً!
  • المشكلة الكبرى: المجاعة (Starvation) للعمليات الطويلة إذا استمر وصول العمليات القصيرة.
Mathematical Formula Predicting Next CPU Burst: Exponential Averaging التنبؤ بفترة المعالج القادمة: المتوسط الأسي

Since the OS cannot know the future, it estimates the length of the next CPU burst ($ au_{n+1}$) based on past behavior using exponential smoothing:

نظراً لأن نظام التشغيل لا يعلم الغيب، فإنه يخمن مدة الاندفاع التالية ($ au_{n+1}$) بناءً على التاريخ السابق باستخدام معادلة التنعيم الأسي:

τn+1 = α · tn + (1 - α) · τn

Where: • tn = Actual length of the n-th CPU burst • τn = Predicted historical value for the n-th CPU burst • α = Weighting factor (0 ≤ α ≤ 1), commonly set to α = 0.5 (1/2)
  • If α = 0: τn+1 = τn → Recent actual history does not count at all; the estimate never adapts.
  • If α = 1: τn+1 = tn → Only the most recent actual burst counts; historical trend is completely discarded.
  • Expanding the formula: each successive historical burst term has progressively less weight due to powers of $(1 - lpha)$.
  • إذا كانت α = 0: تصبح τn+1 = τn ← التاريخ الحديث الفعلي لا يؤثر إطلاقاً، ويبقى التقدير ثابتاً كما هو.
  • إذا كانت α = 1: تصبح τn+1 = tn ← فقط آخر فترة فعلية هي التي تؤخذ في الحسبان، ويتم إهمال التاريخ القديم تماماً.
  • عند فك المعادلة، يقل وزن الفترات السابقة تدريجياً وبشكل أسي لقوى المعامل $(1 - lpha)$.

3️⃣ Priority Scheduling جدولة الأولويات (Priority Scheduling)

Integer Priorities أولويات رقمية Starvation Risk خطر المجاعة

Each process is assigned an integer priority. The CPU is allocated to the process with the highest priority (conventionally, smallest integer = highest priority).

يتم تعيين رقم أولوية صحيح لكل عملية. ويخصص المعالج للعملية ذات الأولوية الأعلى (عادةً: الرقم الأصغر يمثل الأولوية القصوى).

  • Can be preemptive or nonpreemptive.
  • SJF is a special case: where priority = inverse of predicted next CPU burst length ($1 / au$).
  • The Fatal Flaw: Starvation: Low-priority processes may wait forever if high-priority processes keep arriving (in 1973, when MIT's IBM 7094 was shut down, a process submitted in 1967 had never run!).
  • The Elegant Solution: Aging: Gradually increasing the priority of processes as they wait in the ready queue (e.g., increase priority by 1 every 15 minutes).
  • يمكن أن تكون استباقية أو غير استباقية.
  • SJF حالة خاصة منها: حيث تكون الأولوية هي مقلوب وقت الاندفاع المتوقع ($1 / au$).
  • المعضلة الكبرى: المجاعة (Starvation): قد تظل العمليات ذات الأولوية المنخفضة معلقة للأبد (في عام 1973 بمعهد MIT، عند إيقاف حاسوب IBM، وجدوا عملية أُرسلت عام 1967 لم تنفذ أبداً!).
  • الحل الذهبي: التقادم (Aging): زيادة أولوية العملية تدريجياً كلما طال انتظارها في طابور الجاهزية (مثلاً: زيادة الأولوية درجة كل 15 دقيقة).

4️⃣ Round Robin (RR) الجدولة الدورية (Round Robin)

Time-Sharing مشاركة الوقت Fair & Starvation-Free عادلة وبلا مجاعة

Designed specifically for interactive, time-sharing systems. The ready queue is treated as a circular FIFO queue.

صُممت خصيصاً للأنظمة التفاعلية ومشاركة الوقت. يُعامل طابور الجاهزية كـ طابور FIFO دائري.

  • Time Quantum ($q$): Each process receives a small slice of CPU time (usually 10–100 milliseconds). If burst $> q$, the process is preempted and returned to the tail of the ready queue.
  • Guaranteed Wait Bound: If $n$ processes are in the ready queue and quantum is $q$, no process waits more than (n - 1) × q time units for its next turn.
  • Quantum Size Trade-off:
    • If $q o \infty$: RR becomes identical to FCFS.
    • If $q$ is extremely small: Context switch overhead dominates the CPU (processor sharing).
  • Golden Rule: 80% of CPU bursts should be shorter than $q$ to maintain high throughput with low switching overhead.
  • الشريحة الزمنية (Time Quantum $q$): تحصل كل عملية على شريحة صغيرة (عادة 10–100 مللي ثانية). إذا لم تكتمل، تُقطع وتوضع في مؤخرة الطابور.
  • حد الانتظار الأقصى: بوجود $n$ من العمليات، لن تنتظر أي عملية أكثر من (n - 1) × q وحدة زمنية بين كل جولة وأخرى.
  • أثر حجم الشريحة الزمنية $q$:
    • إذا كانت $q$ كبيرة جداً: تتحول الخوارزمية إلى FCFS تماماً.
    • إذا كانت $q$ بالغة الصغر: يضيع معظم وقت المعالج في تبديل السياق (Context Switch Overhead).
  • القاعدة الذهبية: 80% من فترات اندفاع المعالج يجب أن تكون أقصر من $q$.

5️⃣ Multilevel Queue & Multilevel Feedback Queue (MLFQ) الطوابير متعددة المستويات والتغذية الراجعة (MLFQ)

Multilevel Queue (Fixed)
الطوابير متعددة المستويات الثابتة

Ready queue is partitioned into separate queues based on process type:

يُقسم طابور الجاهزية إلى طوابير منفصلة حسب طبيعة العملية:

  • Foreground Queue (Interactive): Uses Round Robin (RR) for fast response.
  • Background Queue (Batch jobs): Uses FCFS for throughput.
  • Inter-queue Scheduling: Fixed priority (risk of starvation) or Time-slice (e.g., 80% CPU to foreground, 20% to background).
  • Processes CANNOT move between queues!
  • طابور المقدمة (Foreground - تفاعلي): يستخدم Round Robin لاستجابة سريعة.
  • طابور الخلفية (Background - دفعات): يستخدم FCFS لزيادة الإنتاجية.
  • الجدولة بين الطوابير: أولوية ثابتة (احتمال مجاعة) أو تقسيم زمني (80% للمقدمة و 20% للخلفية).
  • العملية تظل ثابتة في طابورها ولا تنتقل أبداً!
Multilevel Feedback Queue (MLFQ)
طوابير التغذية الراجعة (MLFQ - مرنة)

Processes CAN move between queues! Provides adaptive scheduling and automatic Aging:

تستطيع العمليات الانتقال بين الطوابير! تدعم الجدولة التكيفية وتطبيق الـ Aging تلقائياً:

  • Queue 0: RR with $q=8$ ms. New jobs enter here. If not finished in 8ms, demoted to Q1.
  • Queue 1: RR with $q=16$ ms. If still not finished, demoted to Q2.
  • Queue 2: FCFS for long compute-bound jobs.
  • Aging: A job waiting too long in lower queues is upgraded to higher queues to prevent starvation.
  • الطابور Q0: خوارزمية RR بشريحة 8 مللي ثانية. تدخل العمليات الجديدة هنا، وإن لم تنتهِ تُنزل إلى Q1.
  • الطابور Q1: خوارزمية RR بشريحة 16 مللي ثانية. إن لم تنتهِ تُنزل إلى Q2.
  • الطابور Q2: خوارزمية FCFS للعمليات الطويلة المستهلكة للمعالج.
  • التقادم (Aging): العمليات التي تنتظر طويلاً في الطوابير السفلى تُرفع إلى طوابير أعلى لمنع المجاعة.

Multiple-Processor & Modern Architecture Scheduling

جدولة المعالجات المتعددة والأنظمة الحديثة

🖥️ AMP vs. SMP & Processor Affinity المعالجة غير المتماثلة والمتماثلة وألفة المعالج

  • Asymmetric Multiprocessing (AMP): Only one master core accesses system data structures; workers execute only user code. Simple, no lock contention, but master is a bottleneck.
  • Symmetric Multiprocessing (SMP): Each processor is self-scheduling from a common ready queue or private ready queues. Most common today.
  • Processor Affinity: A process has an affinity for the processor core on which it is running (due to warm cache memory contents):
    • Soft Affinity: The OS attempts to keep a process on the same CPU, but does not guarantee it.
    • Hard Affinity: The process explicitly specifies CPU sets it can run on (e.g., via sched_setaffinity()).
  • المعالجة غير المتماثلة (AMP): معالج رئيسي واحد (Master) يدير هياكل النظام وجدولة المهام، بينما تنفذ بقية المعالجات كود المستخدم فقط.
  • المعالجة المتماثلة (SMP): كل معالج يقوم بجدولة مهامه ذاتياً، إما من طابور مشترك أو طابور خاص بكل نواة. وهو النموذج السائد اليوم.
  • ألفة المعالج (Processor Affinity): ميل العملية للبقاء على نفس المعالج للاستفادة من محتويات الكاش (Warm Cache):
    • ألفة مرنة (Soft Affinity): يحاول نظام التشغيل إبقاء العملية على نفس المعالج دون إلزام صارم.
    • ألفة صلبة (Hard Affinity): تحديد معالجات معينة لا يجوز للعملية مغادرتها برمجياً.

⚖️ Load Balancing & Multithreaded Cores موازنة الحمل والأنوية متعددة المسارات (Multicore)

  • Load Balancing on SMP: Needed when each processor has its own private queue to keep workloads evenly distributed:
    • Push Migration: A periodic supervisor task checks CPU loads; if an imbalance is found, it pushes tasks from overloaded to idle CPUs.
    • Pull Migration: An idle processor pulls a waiting task from a busy processor's ready queue.
  • Multicore & Memory Stall: Modern processors run much faster than memory. When accessing RAM, a core experiences a memory stall (hundreds of cycles spent waiting).
  • Hardware Multithreading: Cores support multiple hardware threads (e.g., Intel Hyper-Threading). While thread 0 stalls waiting for memory, thread 1 executes instructions on the ALU!
  • موازنة الحمل (Load Balancing): ضرورية عندما يمتلك كل معالج طابوراً خاصاً به:
    • الهجرة بالدفع (Push Migration): مهمة دورية تفحص الأحمال وتدفع المهام من المعالج المزدحم إلى المعالج الخامل.
    • الهجرة بالسحب (Pull Migration): المعالج الخامل يقوم بسحب مهام جاهزة من طابور معالج آخر مزدحم.
  • توقف الذاكرة (Memory Stall): المعالجات أسرع بمراحل من الذاكرة، فعند طلب بيانات من RAM يتوقف المعالج لمئات الدورات بانتظار البيانات.
  • المسارات العتادية المتعددة (Hardware Threads): حل المشكلة عبر دعم خيطين عتاديين لكل نواة؛ فعندما يتعطل الخيط الأول بانتظار الذاكرة، ينفذ الخيط الثاني تعليماته على الفور!

Algorithm Evaluation & Little's Law

طرق تقييم الخوارزميات وقانون ليتل (Little's Law)

📊 Evaluation Methodologies منهجيات تقييم خوارزميات الجدولة

  • Deterministic Modeling: Takes a predetermined, fixed workload (arrival times, burst times) and calculates performance metrics (Gantt chart). Simple and fast, but only valid for that specific dataset.
  • Queueing Models: Uses mathematical probability distributions for arrival rates and service rates to model queue behaviors.
  • Simulations: Generates synthetic workloads or uses recorded system traces (Trace Tapes) to simulate behavior. Accurate but computationally expensive.
  • Implementation: The only 100% accurate method—coding the scheduler directly into the OS kernel and measuring on live production systems.
  • النمذجة الحتمية (Deterministic Modeling): أخذ بيانات محددة مسبقاً وحساب مخطط جانت ومتوسطات الانتظار. بسيطة وسريعة ولكن نتائجها تقتصر على تلك الحالة فقط.
  • نماذج صفوف الانتظار (Queueing Models): استخدام التوزيعات الرياضية الاحتمالية لمعدلات الوصول وخدمة المعالج.
  • المحاكاة (Simulations): محاكاة حركة النظام ببرامج حاسوبية باستخدام أشرطة التتبع المسجلة من أنظمة حقيقية (Trace Tapes). دقيقة لكنها مكلفة ومعقدة.
  • التطبيق الفعلي (Implementation): الطريقة الوحيدة الدقيقة بنسبة 100%—برمجة المجدول فعلياً داخل النواة وقياس الأداء تحت أحمال حقيقية.

📐 Little's Formula (Exam Standard) صيغة وقانون ليتل (سؤال امتحاني شائع)

In steady state, the rate of processes leaving a queue must equal the rate arriving. Little's Law holds for any scheduling algorithm and arrival distribution:

في حالة الاستقرار (Steady State)، فإن معدل مغادرة العمليات يجب أن يساوي معدل وصولها. يصح قانون ليتل مع أي خوارزمية جدولة وتوزيع وصول:

n = λ × W

Where: • n = Average queue length (number of processes in queue) • λ = Average arrival rate into the queue (processes per second) • W = Average waiting time in the queue (seconds)

Solved Example from Lecture Slide 41:
If on average λ = 7 processes arrive per second, and normally n = 14 processes reside in the queue, find average waiting time:
W = n / λ = 14 / 7 = 2 seconds per process!

مثال محلول من سلايد المحاضرة رقم 41:
إذا كان معدل الوصول في المتوسط λ = 7 عمليات في الثانية، ويوجد عادة n = 14 عملية في الطابور، فما هو متوسط زمن الانتظار؟
W = n / λ = 14 / 7 = ثانيتان لكل عملية!

Question 1 of 5 Midterm 2014 • Core Concept ميدتيرم 2014 • مفهوم أساسي
What is the primary performance issue inherently associated with the First-Come, First-Served (FCFS) CPU scheduling algorithm?
ما هي المعضلة الأدائية الجوهرية المرتبطة أساساً بخوارزمية جدولة المعالج (FCFS)؟
Correct Answer: B الإجابة الصحيحة: ب

In FCFS, starvation is completely impossible because every process in the FIFO queue will eventually reach the front and run. The major drawback is the Convoy Effect, where short I/O-bound jobs get bottlenecked behind a single CPU-intensive process, leading to low CPU and device utilization.

في FCFS، يستحيل حدوث مجاعة (Starvation) لأن كل عملية في طابور الـ FIFO ستصل لمقدمة الطابور حتماً. المشكلة الجوهرية هي تأثير القافلة (Convoy Effect) حيث تتعطل العمليات التفاعلية القصيرة خلف عملية حسابية طويلة مما يهدر كفاءة الأجهزة.

Question 2 of 5 Midterm 2021 • Definitions ميدتيرم 2021 • تعاريف
Which operating system component is specifically responsible for context switching, switching to user mode, and jumping to the proper restart location in a user program?
أي مكوّن في نظام التشغيل مسؤول تحديداً عن تبديل السياق، والتحويل لوضع المستخدم، والقفز لموقع الاستئناف المناسب في كود المستخدم؟
Correct Answer: B الإجابة الصحيحة: ب

The short-term scheduler only selects which process runs next. The Dispatcher is the low-level module that gives physical control of the CPU to the selected process by switching context, switching to user mode, and jumping to the instruction counter. The time this takes is called Dispatch Latency.

المجدول قصير المدى يقوم فقط بـ اختيار العملية القادمة من الطابور. أما الموزع (Dispatcher) فهو الوحدة المسؤولة عن تسليم السيطرة الفعلية للمعالج عبر تبديل السياق والانتقال إلى وضع المستخدم والقفز لعنوان البرنامج، وتسمى هذه الفترة Dispatch Latency.

Question 3 of 5 Lecture Slide 17 • Analysis سلايد المحاضرة 17 • تحليل رياضي
In exponential averaging for predicting CPU bursts: τn+1 = α · tn + (1 - α) · τn, what happens if the parameter α is set to 0?
في معادلة التنعيم الأسي للتنبؤ بفترة المعالج: τn+1 = α · tn + (1 - α) · τn، ماذا يحدث عندما تكون قيمة α = 0؟
Correct Answer: B الإجابة الصحيحة: ب

Substituting α = 0 into the formula yields τn+1 = 0 · tn + (1 - 0) τn = τn. Hence, recent execution history does not count at all. Conversely, when α = 1, τn+1 = tn (only the most recent actual burst counts).

بالتعويض عن α = 0 في المعادلة ينتج: τn+1 = τn، وهذا يعني أن ما حدث مؤخراً لا يؤثر على التقدير القادم، بينما إذا كانت α = 1 فإن τn+1 = tn فقط.

Question 4 of 5 Midterm 2014 • True/False Pattern ميدتيرم 2014 • نمط صح/خطأ
Which of the following statements regarding Round-Robin (RR) scheduling is TRUE?
أي العبارات التالية المتعلقة بجدولة Round-Robin (RR) صحيحة تماماً؟
Correct Answer: B الإجابة الصحيحة: ب

If quantum $q$ is extremely large, no process ever exhausts its quantum, meaning each process runs to completion in FIFO arrival order (identical to FCFS). Note: Statement A is false (RR is strictly preemptive), Statement C is inverted (80% of bursts should be shorter than $q$), and Statement D is false (RR is inherently starvation-free).

إذا كانت الشريحة $q$ كبيرة جداً، فلن تنتهي الشريحة قبل انتهاء العملية، وتنفذ العمليات حتى الاكتمال حسب ترتيب وصولها، وهو تعريف FCFS بالضبط. (لاحظ: العبارة أ خاطئة لأن RR استباقية، والعبارة ج مقلوبة لأن 80% يجب أن تكون أقصر من $q$، والعبارة د خاطئة لأن RR مستحيلة المجاعة).

Question 5 of 5 Slide 22 & 41 • Synthesis سلايد 22 و 41 • تطبيق وقوانين
How is process starvation resolved in Priority Scheduling, and which equation represents Little's Law for queueing systems in steady state?
كيف تُحل مشكلة المجاعة (Starvation) في جدولة الأولويات، وما هي معادلة قانون ليتل (Little's Law) لصفوف الانتظار في حالة الاستقرار؟
Correct Answer: A الإجابة الصحيحة: أ

Aging prevents starvation by steadily increasing the priority of processes as they wait. In steady-state queueing theory, Little's Law relates the average queue length ($n$), arrival rate ($\lambda$), and average waiting time ($W$) via the universal formula: n = λ × W.

التقادم (Aging) يمنع المجاعة بزيادة أولوية العملية تدريجياً مع زيادة وقت انتظارها. وقانون ليتل (Little's Law) يربط بين طول الطابور ($n$) ومعدل الوصول ($\lambda$) ومتوسط الانتظار ($W$) بالمعادلة الخالدة: n = λ × W.
