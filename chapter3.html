The Process Concept & Memory Anatomy

مفهوم العملية وتشريحها داخل الذاكرة

💾 Program vs. Process البرنامج (Program) مقابل العملية (Process)

A fundamental exam distinction:

مقارنة امتحانية أساسية ومتكررة:

  • Program (Passive Entity): Stored on secondary storage (disk) as an executable file (e.g., app.exe, a.out). It does nothing until loaded. البرنامج (كيان ساكن Passive): ملف تنفيذي مخزن على القرص، لا يستهلك معالجاً ولا ينفذ أوامر حتى يتم تحميله.
  • Process (Active Entity): A program in execution. It has an active Program Counter (PC), CPU registers, memory allocations, and resources. العملية (كيان نشط Active): برنامج قيد التنفيذ في الذاكرة يمتلك عداد برنامج (PC) ومسجلات وموارد مخصصة.
  • One program can spawn multiple separate processes (e.g., multiple users running the same web browser or multiple terminal sessions). يمكن لبرنامج واحد على القرص أن يُنشئ عدة عمليات متزامنة ومستقلة في الذاكرة.

🧱 The 4 Sections of a Process in Memory الأقسام الأربعة للعملية داخل الذاكرة

When a program loads into RAM, its address space is partitioned into four functional regions:

عند تحميل البرنامج في الذاكرة الرئيسية، تنقسم مساحته العنوانية إلى 4 مناطق:

  • 1. Text Section: Contains the compiled executable machine code instructions. Fixed size and usually read-only. 1. قسم النص (Text Section): يحتوي على الكود البرمجي التنفيذي (تعليمات الآلة). حجمه ثابت وهو للقراءة فقط.
  • 2. Data Section: Stores global variables and static variables allocated before program execution begins. 2. قسم البيانات (Data Section): يحتوي على المتغيرات العامة (Global) والمتغيرات الساكنة (Static).
  • 3. Stack (Grows Downward): Stores temporary data including function parameters, return memory addresses, and local variables. 3. المكدس (Stack): يحتوي على البيانات المؤقتة: معاملات الدوال، عناوين العودة، والمتغيرات المحلية (Local Variables). ينمو لأسفل.
  • 4. Heap (Grows Upward): Memory dynamically allocated at runtime via malloc() in C or new in C++/Java. 4. الكومة (Heap): الذاكرة المخصصة ديناميكياً أثناء وقت التشغيل عبر malloc() أو new. تنمو لأعلى باتجاه المكدس.

Process States, PCB & Context Switching

حالات العملية، كتلة التحكم (PCB) والتبديل السياقي

🔄 The 5 Process States حالات العملية الخمس

As a process executes, it transitions through five distinct states:

أثناء دورة حياة العملية، تنتقل بين خمس حالات رئيسية:

  • New: The process is being created. جديدة (New): العملية قيد الإنشاء والتجهيز.
  • Running: Instructions are being actively executed on a CPU core. قيد التنفيذ (Running): التعليمات تُنفذ حالياً على المعالج.
  • Waiting (Blocked): The process is waiting for some external event to occur (such as I/O completion or reception of a signal). في الانتظار (Waiting): تنتظر وقوع حدث خارجي (مثل اكتمال I/O أو وصول إشارة).
  • Ready: The process is loaded in main memory and waiting to be assigned to a processor by the CPU scheduler. جاهزة (Ready): محملة بالذاكرة وجاهزة تماماً، وتنتظر فقط تخصيص المعالج لها.
  • Terminated: The process has finished execution and released its memory. منتهية (Terminated): أتمت التنفيذ وحررت مواردها.

📋 Process Control Block (PCB) كتلة التحكم بالعملية (PCB)

The data structure in the kernel representing a process. It contains:

هيكل بيانات داخل النواة يمثل بطاقة هوية العملية وسجلها، ويحتوي على:

  • Process State: New, ready, running, waiting, or terminated. حالة العملية الحالية.
  • Program Counter (PC): Address of the next instruction to execute. عداد البرنامج: عنوان التعليمة التالية للتنفيذ.
  • CPU Registers: Accumulators, index registers, stack pointers, general registers. مسجلات المعالج ومؤشر المكدس.
  • CPU Scheduling Info: Priority and queue pointers. أولوية العملية ومؤشرات طوابير الجدولة.
  • Memory-Management Info: Base/limit registers or page/segment tables. معلومات الذاكرة وجداول الصفحات المخصصة لها.
  • Accounting & I/O Status Info: CPU time consumed, open files list, allocated I/O devices. معلومات الحسابات وقائمة الملفات المفتوحة وأجهزة I/O المخصصة.
💡
Hard Concept Breakdown: What Really Happens During a Context Switch? تبسيط مفهوم معقد: ماذا يحدث بالدقة أثناء التبديل السياقي (Context Switch)؟

When the CPU switches from running Process $P_0$ to Process $P_1$:

عندما يقرر المعالج التبديل من تنفيذ العملية $P_0$ إلى العملية $P_1$:

1

Save State of $P_0$ into $PCB_0$

حفظ حالة العملية القديمة في $PCB_0$

The kernel saves current Program Counter, CPU registers, and status flags into $P_0$'s Process Control Block.

تحفظ النواة عداد البرنامج والمسجلات الحالية داخل كتلة التحكم $PCB_0$.

2

CPU Scheduler Selects $P_1$

المجدول يختار العملية التالية $P_1$

Scheduler selects next ready process $P_1$ from the ready queue and updates process states.

يختار مجدول المعالج العملية التالية $P_1$ من طابور الجاهزية ويحدث حالتها إلى Running.

3

Load State of $P_1$ from $PCB_1$

استرجاع حالة العملية الجديدة من $PCB_1$

The kernel restores the saved registers, stack pointer, and Program Counter from $PCB_1$ into CPU registers.

تسترجع النواة المسجلات ومؤشر المكدس وعداد البرنامج الخاص بالعملية $P_1$ إلى عتاد المعالج.

Resume Execution & Overhead Reality

استئناف التنفيذ وحقيقة الهدر الزمني (Overhead)

CPU resumes executing $P_1$. Crucial Exam Fact: Context switch time is pure overhead—the system performs NO useful work while switching states!

يبدأ المعالج تنفيذ $P_1$. حقيقة امتحانية هامة: زمن تبديل السياق هو هدر محض (Overhead) ولا ينجز النظام أي عمل مفيد أثنائه!

Explanation: That is the definition of the Waiting (Blocked) state. The Ready state describes a process that has everything it needs and is waiting only to be allocated a CPU!

التعليل: انتظار الأحداث هو تعريف حالة الانتظار (Waiting). أما حالة الجاهزية (Ready) فتصف العملية الجاهزة بالكامل والتي تنتظر فقط تخصيص المعالج لها!
ميدتيرم 2021 سؤال 1.6: "يقوم تبديل السياق (Context switch) بحفظ حالة العملية الحالية واسترجاع حالة العملية التالية للتشغيل."

Process Scheduling: Queues & The 3 Schedulers

جدولة العمليات: الطوابير والمجدولات الثلاثة

🚶‍♂️ The 3 Scheduling Queues طوابير الجدولة الثلاثة

Processes migrate among queues during their lifetime:

تهاجر العمليات بين طوابير مختلفة أثناء وجودها بالنظام:

  • Job Queue: Set of all processes present in the system (including jobs on disk awaiting admission). طابور الوظائف (Job Queue): يحتوي على كافة العمليات الموجودة في النظام ككل.
  • Ready Queue: Set of all processes residing in main memory (RAM), ready and waiting for CPU allocation. طابور الجاهزية (Ready Queue): العمليات المقيمة في RAM والجاهزة لانتزاع المعالج.
  • Device Queues: Set of processes waiting for a specific I/O device (e.g., disk queue, printer queue). طوابير الأجهزة (Device Queues): العمليات التي تنتظر إتاحة جهاز إدخال/إخراج محدد. (سؤال ميدتيرم 2021 Q1.3).

⚖️ Degree of Multiprogramming درجة البرمجة المتعددة (Degree of Multiprogramming)

Defined as the total number of processes in main memory.

تُعرّف بأنها العدد الإجمالي للعمليات المقيمة في الذاكرة الرئيسية (RAM).

  • I/O-Bound Process: Spends more time doing I/O than computations; characterized by many short CPU bursts. عملية مقيدة بـ I/O: تقضي وقتاً في الإدخال/الإخراج أكثر من الحسابات؛ نبضات معالج قصيرة وكثيرة.
  • CPU-Bound Process: Spends more time doing computations; characterized by very few, long CPU bursts. عملية مقيدة بالمعالج: تقضي معظم وقتها في الحسابات؛ نبضات معالج طويلة وقليلة.
  • The OS strives for a good process mix of both types to keep CPU and I/O devices concurrently busy. يسعى النظام لتحقيق مزيج متوازن بين النوعين لإشغال المعالج وأجهزة I/O في نفس الوقت.

The Three Schedulers Compared (Midterm Essay Question)

مقارنة شاملة بين المجدولات الثلاثة (سؤال مقالي في امتحان 2014)

Feature وجه المقارنة Long-Term Scheduler (Job Scheduler) المجدول طويل الأجل (Job Scheduler) Short-Term Scheduler (CPU Scheduler) المجدول قصير الأجل (CPU Scheduler) Medium-Term Scheduler (Swapper) المجدول متوسط الأجل (Swapper)
Primary Task المهمة الأساسية Selects jobs from disk pool and loads them into memory (Ready Queue). يختار العمليات من القرص ويحملها للذاكرة (Ready Queue). Selects which process from the ready queue executes next and allocates CPU. يختار العملية التالية للتنفيذ ويخصص لها المعالج (CPU). Removes processes from memory to disk and brings them back (Swapping). ينقل العمليات مؤقتاً للقرص ويعيدها (المبادلة Swapping).
Invocation Frequency معدل الاستدعاء Very infrequent (seconds, minutes); can be relatively slow. نادر الاستدعاء (كل ثوانٍ أو دقائق)؛ قد يكون بطيئاً. Extremely frequent (milliseconds); must be very fast. متكرر وسريع جداً (كل عدة ميلي ثوانٍ)؛ يجب أن يكون فائق السرعة. Intermediate frequency as needed during high memory pressure. متوسط الاستدعاء حسب ضغط الذاكرة.
Control Over Multiprogramming التحكم في درجة البرمجة المتعددة Directly controls the degree of multiprogramming. يتحكم مباشرة في درجة البرمجة المتعددة بزيادتها. Has NO control over the degree of multiprogramming. لا يتحكم إطلاقاً في درجة البرمجة المتعددة. Reduces degree of multiprogramming when RAM is overloaded. يقلل درجة البرمجة المتعددة لتخفيف العبء.

Process Operations: Creation, Forking & Termination

عمليات التشغيل: إنشاء العمليات، التفرع fork() والإنهاء

🌳 Process Creation & Forking إنشاء العمليات والتفرع (fork)

In UNIX/Linux, processes form a tree hierarchy with init (or systemd, PID = 1) at the root:

في أنظمة UNIX/Linux، تشكل العمليات شجرة هرمية تبدأ من جذر النظام init (رقم PID = 1):

  • fork() System Call: Creates a new process. The child process is an exact duplicate of the parent's address space. Both processes continue execution from the instruction following fork()! استدعاء fork(): ينشئ عملية ابن تكون نسخة مطابقة تماماً للمسار والعنوان البرمجي للأب، ويكمل كلاهما التنفيذ من النقطة التالية لـ fork().
  • Return Value of fork(): Returns 0 to the child process, and returns the child's PID to the parent process. قيمة العودة: يعيد 0 للعملية الابن، ويعيد رقم PID للابن للعملية الأب.
  • exec() System Call: Used after fork() to overwrite the process memory space with an entirely new program binary (e.g., running /bin/ls). استدعاء exec(): يُستخدم بعد fork() لاستبدال محتوى الذاكرة بالكامل ببرنامج تنفيذي جديد.
  • wait() System Call: The parent can call wait() to suspend execution until the child terminates. استدعاء wait(): يعلق تنفيذ الأب حتى ينتهي الابن تماماً من عمله.

🛑 Process Termination & Special States إنهاء العمليات والحالات الخاصة

A process finishes by invoking the exit() system call:

تنهي العملية تنفيذها باستدعاء exit():

  • Cascading Termination: In some operating systems, if a parent process terminates, all of its children must also be terminated immediately. الإنهاء التتالي (Cascading Termination): إنهاء فوري لكافة الأبناء إذا انتهت العملية الأب.
  • Zombie Process: A process that has terminated, but whose parent has not yet called wait() to read its exit status. It remains in the process table. العملية الشبح (Zombie): عملية انتهت لكن لم يستدعِ الأب wait() لقراءة حالتها، فتبقى بياناتها بجدول العمليات.
  • Orphan Process: A process whose parent has terminated without invoking wait(). Linux re-parents orphans to init (PID 1). العملية اليتيمة (Orphan): عملية انتهى والدها دون استدعاء wait()، فيتولى init تبنيها.

5

Interprocess Communication (IPC): Models & Mechanisms

التواصل بين العمليات (IPC): النماذج والآليات (سؤال مقالي 2022)

🔄 Shared Memory Model نموذج الذاكرة المشتركة (Shared Memory)

A region of memory shared by cooperating processes:

منطقة ذاكرة فيزيائية مشتركة تصل إليها العمليات المتعاونة:

  • Maximum Speed: Extremely fast; data exchange occurs at hardware memory speeds without kernel intervention after setup. سرعة قصوى: فائقة السرعة؛ يتم تبادل البيانات بسرعة الذاكرة دون تدخل النواة بعد إنشاء المنطقة.
  • Producer-Consumer Problem: Producer produces data items into a buffer; Consumer consumes them. Implemented via circular bounded buffer (maximum items = BUFFER_SIZE - 1). مسألة المنتج والمستهلك: تخزين في مخزن دائري محدود (يتسع لـ BUFFER_SIZE - 1 لتفادي الخلط بين الامتلاء والفراغ).
  • Challenge: Application programmers must explicitly handle process synchronization to prevent race conditions. التحدي: يقع عبء التزامن وتفادي تضارب البيانات بالكامل على عاتق المبرمج.

✉️ Message Passing Model نموذج تمرير الرسائل (Message Passing)

Processes communicate and synchronize without sharing variables:

تتواصل العمليات وتتزامن دون الحاجة لمشاركة مساحة ذاكرة أو متغيرات:

  • Primitives: send(message) and receive(message). الدوال الأساسية: الإرسال send(message) والاستقبال receive(message).
  • Distributed Friendly: Particularly useful in distributed and networked environments (Client-Server). مثالية للشبكات: ممتازة في الأنظمة الموزعة والشبكات لعدم الحاجة لذاكرة مشتركة.
  • Kernel Involvement: Slower than shared memory because messages must be copied across user-kernel boundaries by system calls. تدخل النواة: أبطأ من الذاكرة المشتركة بسبب نسخ البيانات بين مساحة المستخدم والنواة.

Direct vs. Indirect Communication (Midterm 2022 Essay Question)

مقارنة بين الاتصال المباشر وغير المباشر (سؤال مقالي ميدتيرم 2022)

Feature وجه المقارنة Direct Communication (الاتصال المباشر) الاتصال المباشر (Direct) Indirect Communication (الاتصال غير المباشر) الاتصال غير المباشر (Indirect)
Addressing / Naming طريقة العنونة والتسمية Processes must name each other explicitly: send(P, msg), receive(Q, msg). تسمية صريحة للطرف الآخر: send(P, msg). Messages sent to and received from Mailboxes or Ports: send(A, msg). ترسل وتستقبل عبر صناديق البريد (Mailboxes/Ports): send(A, msg).
Link Association ارتباط مسار الاتصال A link is associated with exactly two processes. يرتبط المسار بـ عمليتين اثنتين فقط لا غير. A link can be associated with many processes sharing the mailbox. يمكن أن يشترك في المسار عدة عمليات متعددة.
Number of Links عدد المسارات بين كل زوج Between each pair of processes, there exists exactly one link. يوجد مسار واحد فقط بين كل زوج من العمليات. Each pair of processes may share several distinct links (multiple mailboxes). يمكن لزوج العمليات أن يتشارك عدة مسارات مختلفة عبر صناديق بريد متعددة.
Link Establishment إنشاء المسار Established automatically when processes address each other. يُنشأ تلقائياً بمجرد ذكر اسم العملية الأخرى. Established only if processes share a common mailbox/port. يُنشأ فقط إذا تشاركت العمليتان نفس صندوق البريد.

Chapter 3 Key Terms & Exam Glossary

قاموس المصطلحات والمفاهيم الأساسية للفصل الثالث

Process
العملية (Process)

A program in execution; an active entity with text, stack, data, heap, and a program counter.

برنامج قيد التنفيذ؛ كيان نشط يتضمن كود الآلة، المكدس، البيانات، الكومة، وعداد البرنامج.

Context Switch
تبديل السياق (Context Switch)

The mechanism of saving the state of the current process into its PCB and restoring the state of the next process to run (pure overhead).

آلية حفظ حالة العملية الحالية في كتلتها واسترجاع حالة العملية التالية لتشغيلها (هدر زمني دون عمل نافع).

Rendezvous
التزامن التام (Rendezvous)

A tightly synchronized message-passing state occurring when both send() and receive() are blocking.

حالة تزامن دقيقة تحدث عندما تكون عمليتا الإرسال والاستقبال كلتاهما حاجزة ومقيدة (Blocking).

Degree of Multiprogramming
درجة البرمجة المتعددة

The number of processes loaded in main memory at the same time; directly controlled by the long-term scheduler.

عدد العمليات المقيمة في الذاكرة الرئيسية في نفس اللحظة؛ ويتحكم بها المجدول طويل الأجل.

fork() & exec()
استدعاءات fork و exec

fork() duplicates the parent's address space creating a child; exec() loads a new program into that space.

استدعاء fork() ينسخ مساحة عنوان الأب للابن؛ بينما exec() يستبدلها ببرنامج تنفيذي جديد.

Mailbox / Port
صندوق البريد / المنفذ (Port)

An intermediate abstraction used in indirect message passing allowing multiple processes to communicate asynchronously.

وسيط تخزين وتوجيه يُستخدم في الاتصال غير المباشر لتبادل الرسائل بين عدة عمليات.
