What Operating Systems Do & Core Definitions

ماذا تفعل أنظمة التشغيل والتعريفات الجوهرية

💻 Definition & Dual Views التعريف والمنظوران الأساسيان

An Operating System (OS) is a program that acts as an intermediary between a user of a computer and the computer hardware.

نظام التشغيل (OS) هو برنامج يعمل كوسيط بين مستخدم الحاسوب والعتاد المادي (Hardware).

  • User View: Focused on convenience, ease of use, and good performance. Users generally do not care about overall resource utilization on personal devices. منظور المستخدم (User View): يركز على السهولة، راحة الاستخدام، وسرعة الاستجابة، دون الاكتراث بكفاءة استغلال الموارد الإجمالية.
  • System View: The OS is a Resource Allocator (managing CPU time, memory space, file storage, and I/O devices fairly) and a Control Program (preventing errors and improper computer usage). منظور النظام (System View): نظام التشغيل هو موزع للموارد (يفصل في الطلبات المتعارضة بعدالة وكفاءة) وبرنامج تحكم (يمنع الأخطاء وسوء استخدام العتاد).

⚙️ The Kernel & Startup Process النواة (Kernel) وإقلاع النظام

No universally accepted definition exists for everything shipped in an OS, but computer science defines the Kernel as "the one program running at all times on the computer".

لا يوجد تعريف موحد لكل ما يُشحن مع النظام، لكن المصطلح الأكاديمي الدقيق لـ النواة (Kernel) هو "البرنامج الوحيد الذي يعمل طوال الوقت على الحاسوب".

  • System Programs: Associated with the OS but not part of the kernel (e.g., shell, compilers, system daemons). برامج النظام (System Programs): تأتي مع النظام لكنها خارج النواة (مثل مفسر الأوامر Shell والأدوات الخدمية).
  • Bootstrap Program: Stored in ROM or EEPROM (Firmware). Initialized at power-up/reboot, initializes registers, memory, and device controllers, then locates and loads the OS kernel into RAM to start execution. برنامج الإقلاع (Bootstrap Program): مخزن في الذاكرة الدائمة ROM أو EEPROM (Firmware). يُحمّل فور تشغيل الحاسوب، ويهيئ المسجلات والذاكرة، ثم يحمل النواة إلى RAM ويبدأ تشغيلها.

Computer-System Organization & The Interrupt Mechanism

تنظيم نظام الحاسوب وآلية المقاطعات (Interrupts)

⚡ Interrupt-Driven Nature طبيعة النظام القائم على المقاطعات

Modern operating systems are fundamentally Interrupt-Driven. If there are no processes to execute, no I/O devices requesting service, and no user input, the OS remains idle waiting for an interrupt event.

تعتبر أنظمة التشغيل الحديثة أنظمة مدفوعة بالمقاطعات (Interrupt-Driven Systems). إذا لم توجد عمليات للتنفيذ أو أجهزة إدخال/إخراج تطلب خدمة، يقف النظام في حالة ترقب وانتظار لوقوع حدث مقاطعة.

  • Hardware Interrupt: Triggered by physical hardware devices sending an electrical signal across the system bus to the CPU (e.g., keyboard keystroke, disk transfer finished). مقاطعة مادية (Hardware Interrupt): يرسلها أحد أجهزة العتاد المادي عبر مسار النظام (Bus) إلى المعالج (مثل ضغطة مفتاح أو انتهاء قراءة القرص).
  • Software Interrupt (Trap / Exception): Generated by software due to an error (e.g., division by zero, invalid memory address) or a deliberate user request for an OS service (System Call). مقاطعة برمجية (Trap / Exception): تنتج برمجياً بسبب خطأ (مثل القسمة على صفر أو تجاوز عنوان الذاكرة) أو طلب خدمة نظام متعمد (استدعاء النظام System Call).

🔀 Interrupt Architecture & ISR بنية المقاطعات وروتين الخدمة (ISR)

When an interrupt signals the CPU:

عندما يستقبل المعالج إشارة مقاطعة:

  • State Saving: The CPU immediately suspends execution and saves its current state (Program Counter and CPU registers) so it can resume later without loss of data. حفظ الحالة (State Saving): يُوقف المعالج العمل ويحفظ عداد البرنامج (PC) ومسجلات المعالج للعودة لاحقاً دون ضياع للبيانات.
  • Interrupt Vector: An array of memory pointers holding the exact starting addresses of all specialized Interrupt Service Routines (ISRs). Indexed directly by interrupt number. جدول متجه المقاطعات (Interrupt Vector): مصفوفة مؤشرات تحتوي على عناوين بدء كافة روتينات خدمة المقاطعة (ISRs)، مفهرسة برقم المقاطعة.
  • Vectored vs Polling: Vectored interrupts branch immediately using the vector address; polling iterates through devices asking each if it raised the interrupt. الموجهة مقابل الاستطلاع: المقاطعة الموجهة تقفز فوراً لعنوان الروتين؛ بينما الاستطلاع (Polling) يسأل الأجهزة واحداً تلو الآخر إن كان هو صاحب المقاطعة.

Hard Concept Breakdown: The Complete Interrupt Execution Lifecycle تبسيط مفهوم معقد: دورة حياة المقاطعة خطوة بخطوة

Students often confuse what the CPU hardware does automatically versus what the OS software does. Here is the exact chronological sequence:

غالباً ما يختلط على الطلاب ما يقوم به عتاد المعالج تلقائياً وما يقوم به كود نظام التشغيل. إليك التسلسل الزمني الدقيق:

1

Device Controller Signals Interrupt

وحدة التحكم بالجهاز ترسل إشارة مقاطعة

Device finishes operation and asserts an interrupt signal line on the system bus.

ينتهي الجهاز من العملية ويرسل إشارة المقاطعة عبر مسار النظام للمعالج.

2

Hardware State Preservation

حفظ حالة العتاد تلقائياً

Before jumping, the CPU pushes the current Program Counter (PC) and status registers onto the system stack.

يقوم المعالج عتادياً بحفظ عداد البرنامج الحالي ومسجلات الحالة في مكدس النظام (System Stack).

3

Vector Table Lookup & Dispatch

البحث في جدول المتجهات والقفز

CPU reads the interrupt index, looks up the ISR address in the Interrupt Vector, and loads it into the Program Counter.

يقرأ المعالج رقم المقاطعة ويجلب عنوان الروتين المناسب من جدول المتجهات ويضعه في عداد البرنامج.

4

ISR Execution & State Restoration

تنفيذ الروتين واستعادة الحالة

The ISR handles the device event (e.g., transfers buffer data), executes an 'interrupt return' instruction, restoring registers and resuming the original user program seamlessly.

ينفذ روتين المقاطعة الإجراء (كنقل البيانات من مخزن الجهاز)، ثم ينفذ أمر العودة من المقاطعة، مستعيداً المسجلات ومستأنفاً البرنامج الأصلي.

I/O Structure, DMA & Storage Hierarchy

بنية الإدخال/الإخراج، النفاذ المباشر للذاكرة (DMA) وتدرج التخزين

🔄 Synchronous vs. Asynchronous I/O الإدخال والإخراج المتزامن مقابل غير المتزامن

How the OS handles execution flow after an I/O request defines the I/O model:

تحدد استجابة نظام التشغيل بعد طلب الإدخال/الإخراج نموذج العمل المتبع:

  • Synchronous I/O: Control returns to user program only after the I/O finishes. The CPU idles in a wait loop or wait instruction until the interrupt occurs. Only one I/O operation can be processed at a time. المتزامن (Synchronous): لا تعود السيطرة لبرنامج المستخدم إلا بعد اكتمال الإدخال/الإخراج. يقف المعالج عاطلاً ينتظر المقاطعة، وتُنفذ عملية واحدة فقط في المرة.
  • Asynchronous I/O: Control returns to the user program without waiting for I/O completion. A Device-Status Table tracks multiple pending requests concurrently. غير المتزامن (Asynchronous): تعود السيطرة لبرنامج المستخدم فوراً دون انتظار انتهاء العملية. يُستخدم جدول حالة الأجهزة لإدارة الطلبات المتزامنة.

🚀 Direct Memory Access (DMA) النفاذ المباشر للذاكرة (DMA)

Standard interrupt I/O interrupts the CPU for every single byte of transferred data. For high-speed devices (disks, gigabit Ethernet), this creates disastrous CPU overhead.

في الإدخال/الإخراج المعتاد، يتم مقاطعة المعالج عند نقل كل بايت منفرد، مما يسبب إرهاقاً هائلاً للمعالج عند التعامل مع أجهزة فائقة السرعة كالأقراص والشبكات.

  • DMA Controller: Transfers an entire block of data directly between its local buffer and main memory without CPU intervention. وحدة DMA: تنقل كتلة كاملة من البيانات مباشرة بين مخزن الجهاز وذاكرة RAM دون إقحام المعالج.
  • Efficiency: Generates only one interrupt per block instead of one interrupt per byte, freeing the CPU to perform computation. الكفاءة: تُطلق مقاطعة واحدة فقط لكل كتلة بيانات كاملة بدلاً من مقاطعة لكل بايت، مما يوفر وقت المعالج.

Must-Know Exam Traps (Storage & Caching) أفخاخ امتحانية شائعة (التخزين والكاش) Midterm 2019 & 2022

Exam 2019 T/F Question: "Solid-state disks are nonvolatile and in general are slower than magnetic disks." ➔ FALSE! SSDs are faster than magnetic disks.
Exam 2022 Definition: "Caching:" Copying information into a faster storage system temporarily. Faster storage is checked first; if data resides there, it is used directly (Cache Hit); otherwise it is copied from slower storage (Cache Miss).
Cache Coherency: In multiprocessor systems where each CPU has its own local cache, hardware must ensure that an update made by one CPU is immediately visible across all other CPU caches.

سؤال صح/خطأ (ميدتيرم 2019): "أقراص الحالة الصلبة (SSD) غير متطايرة وهي عموماً أبطأ من الأقراص الممغنطة." ➔ خطأ (False)! لأنها أسرع بكثير.
سؤال تعريف (ميدتيرم 2022): "الكاشينج (Caching):" نسخ المعلومات مؤقتاً في وسيط تخزين أسرع. يتم فحص الكاش أولاً؛ فإن وُجدت استُخدمت مباشرة (Cache Hit)، وإن لم توجد نُسخت من الوسط الأبطأ (Cache Miss).
اتساق الكاش (Cache Coherency): في الأنظمة متعددة المعالجات حيث يمتلك كل معالج كاش خاص به، يجب أن يضمن العتاد تحديث القيمة في كاش جميع المعالجات عند تعديلها في أي معالج.

Computer-System Architecture: Multiprocessors & Multicore

بنية أنظمة الحاسوب: المعالجات المتعددة ومتعددة الأنوية

✨ 3 Multiprocessor Advantages مزايا الأنظمة متعددة المعالجات الثلاث

Systems having two or more processors in close communication sharing the computer bus, clock, memory, and peripheral devices provide:

الأنظمة التي تحتوي على معالجين أو أكثر متصلين ببعضهم ويشتركون في مسار النظام، الساعة، الذاكرة والأجهزة الطرفية، تقدم 3 مزايا:

  • 1. Increased Throughput: By adding more processors, more work is completed in less time (though speedup ratio is not strictly N due to overhead and contention). 1. زيادة الإنتاجية (Throughput): إنجاز عمل أكبر في زمن أقل.
  • 2. Economy of Scale: Costs significantly less than equivalent separate single systems because they share power supplies, memory, and mass storage. 2. اقتصاد الحجم (Economy of Scale): تكلفة أقل لمشاركة مزود الطاقة، الذاكرة والتخزين مقارنة بأجهزة منفردة متعددة.
  • 3. Increased Reliability: Graceful degradation or Fault Tolerance. If one processor fails, the entire system does not crash; it simply continues operating at a slightly reduced speed. 3. زيادة الاعتمادية (Reliability): التدهور التدريجي ومقاومة الأعطال؛ إذا تعطل معالج لا يتوقف النظام بأكمله، بل يكمل العمل بسرعة أقل.

⚙️ AMP vs. SMP Multiprocessing المعالجة غير المتماثلة (AMP) مقابل المتماثلة (SMP)

The two dominant multiprocessor paradigms:

النموذجان الرئيسيان للمعالجة المتعددة:

  • Asymmetric Multiprocessing (AMP): "Boss-Worker" model. A master/boss processor controls the system, manages resources, and schedules specific tasks to worker processors. غير المتماثلة (AMP): نموذج "الرئيس والعمال (Boss-Worker)". معالج رئيسي يدير النظام ويوزع المهام على المعالجات الأخرى.
  • Symmetric Multiprocessing (SMP): All processors are Peers. No boss-worker relationship exists; each processor runs an identical copy of the OS and executes tasks concurrently. المتماثلة (SMP): جميع المعالجات أقران متساوون (Peers). لا يوجد رئيس؛ كل معالج ينفذ نسخة نظام التشغيل والمهام بالتوازي.

OS Structure, Dual-Mode Protection & Hardware Timer

هيكلية النظام، حماية الوضع المزدوج (Dual-Mode) ومؤقت العتاد

📊 Multiprogramming vs. Multitasking البرمجة المتعددة مقابل مشاركة الوقت

Two foundational concepts that students frequently mix up on exams:

مفهومان جوهريان يكثر الخلط بينهما في الامتحانات:

  • Multiprogramming: Keeps multiple jobs in memory simultaneously. When the currently running job must wait (e.g., for I/O), the OS switches the CPU to another job. Primary Goal: MAXIMIZE CPU utilization so the processor is never idle. البرمجة المتعددة (Multiprogramming): الاحتفاظ بعدة وظائف في الذاكرة معاً. عندما تنتظر العملية الحالية الإدخال/الإخراج، يُسند المعالج لعملية أخرى. الهدف الأساسي: تعظيم استغلال المعالج (Maximize CPU utilization).
  • Multitasking (Timesharing): A logical extension of multiprogramming. The CPU switches between jobs so rapidly (in milliseconds) that users can interact with each program while it runs. Primary Goal: MINIMIZE response time (< 1 second) for interactive computing. مشاركة الوقت (Timesharing / Multitasking): امتداد منطقي للبرمجة المتعددة. يبدل المعالج بين العمليات بسرعة فائقة تمكّن المستخدمين من التفاعل المباشر مع برامجهم. الهدف الأساسي: تقليل زمن الاستجابة (Minimize response time).

🛡️ Dual-Mode Operation & Mode Bit الوضع المزدوج (Dual-Mode) وبت الوضع

To prevent rogue or faulty user programs from crashing the entire system or tampering with other users' memory, hardware provides a Mode Bit:

لحماية النظام من برامج المستخدم الخاطئة أو الخبيثة من إسقاط النظام أو التلاعب بذاكرة الآخرين، يوفر العتاد بت الوضع (Mode Bit):

  • User Mode (Mode bit = 1): Code executed on behalf of the user. Cannot execute privileged instructions directly. وضع المستخدم (User Mode - بت = 1): يتم فيه تنفيذ كود المستخدم، وممنوع من تشغيل الأوامر المحمية مباشرة.
  • Kernel / Supervisor Mode (Mode bit = 0): Code executed on behalf of the OS. Full access to hardware, all memory, and privileged instructions. وضع النواة (Kernel Mode - بت = 0): ينفذ كود نظام التشغيل، وله صلاحية مطلقة على العتاد والأوامر المحمية.
  • Privileged Instructions: Can ONLY be executed in kernel mode (e.g., direct I/O control, clearing memory, disabling interrupts, modifying the timer, and changing the mode bit!). الأوامر المحمية (Privileged Instructions): لا يمكن تنفيذها إلا في وضع النواة (مثل أوامر I/O، تعديل المؤقت، تعطيل المقاطعات، وتغيير بت الوضع!).
Dimension وجه المقارنة Multiprogramming البرمجة المتعددة (Multiprogramming) Multitasking / Timesharing مشاركة الوقت (Timesharing)
Core Objective الهدف الجوهري Keep CPU busy at all times (Maximize CPU utilization). إشغال المعالج دائماً وتعظيم كفاءة استغلاله. Provide fast interactive user response time (< 1 sec). توفير زمن استجابة تفاعلي سريع جداً للمستخدم.
Switching Trigger سبب التبديل بين العمليات Switches only when current job blocks for I/O or an event. التبديل يحدث فقط عند انتظار العملية لـ I/O. Switches frequently based on time slices (Timer quantum). التبديل مستمر وسريع وفق شرائح زمنية يحددها المؤقت.
User Interaction تفاعل المستخدم Non-interactive (batch jobs submitted and queued). غير تفاعلي غالباً (معالجة دفعات Batch). Direct, highly interactive multi-user environment. تفاعلي مباشر بين المستخدم والنظام أثناء التنفيذ.
📌
Must-Know Exam Traps (Dual Mode & Multiprogramming) فخاخ امتحانية مؤكدة (الوضع المزدوج والبرمجة المتعددة) Midterm 2014 & 2019

Midterm 2014 T/F: "The objective of multiprogramming is to have some process running at all times, to minimize CPU utilization." ➔ FALSE! It is to maximize CPU utilization.
Midterm 2019 T/F: "The instruction to switch to user mode is an example of a privileged instruction." ➔ TRUE! Any instruction that modifies the mode bit is strictly privileged. A user program cannot simply declare itself in kernel mode.
Hardware Timer: Prevents user programs from monopolizing the CPU or running in infinite loops. The OS sets the timer before dispatching a process. When the timer decrements to 0, it triggers an interrupt, returning control back to the OS.

ميدتيرم 2014 صح/خطأ: "الهدف من البرمجة المتعددة هو إبقاء عملية تعمل طوال الوقت لتقليل استغلال المعالج (minimize)." ➔ خطأ (False)! الهدف هو تعظيم (maximize) استغلال المعالج.
ميدتيرم 2019 صح/خطأ: "أمر التبديل إلى وضع المستخدم هو مثال على أمر محمي (Privileged Instruction)." ➔ صحيح (True)! لأن التلاعب ببت الوضع محصور بالنواة فقط.
مؤقت العتاد (Hardware Timer): يمنع استئثار برنامج المستخدم بالمعالج أو دخوله في حلقة مفرغة (Infinite Loop) عبر إطلاق مقاطعة قسرية عند وصول العداد لصفر لاستعادة النواة لزمام الأمور.

Computing Environments: Virtualization, Cloud & Real-Time

بيئات الحوسبة: الحوسبة الافتراضية، السحابية والأنظمة اللحظية

📦 Virtualization vs. Emulation البيئات الافتراضية (Virtualization) مقابل المحاكاة (Emulation)

Crucial architectural difference:

فارق جوهري في بنية التشغيل:

  • Emulation: Used when the target computer hardware architecture differs from the host (e.g., running Intel x86 code on an ARM CPU). Translates instructions in software; slowest execution method. المحاكاة (Emulation): تُستخدم عندما يختلف معمار عتاد المصدر عن الهدف (مثل تشغيل كود Intel x86 على معالج ARM). يتم ترجمة الأوامر برمجياً وهو الأسلوب الأبطأ.
  • Virtualization: Guest OS is natively compiled for the same CPU architecture as the host. The Virtual Machine Manager (VMM / Hypervisor) allows guest OSs to run with near-native hardware speed. الافتراضية (Virtualization): نظام الضيف مترجم أصلاً لنفس معمارية المعالج، ويتولى مدير الأجهزة الافتراضية (VMM) تشغيله بسرعة تقارب سرعة العتاد الأصلي.

⏱️ Real-Time Embedded Systems الأنظمة المدمجة ذات الوقت الحقيقي (Real-Time)

The most prevalent form of computers worldwide (automotive, robotics, medical instruments, avionics):

أكثر أشكال الحواسيب انتشاراً في العالم (السيارات، الروبوتات، الأجهزة الطبية، الملاحة الجوية):

  • Rigid Time Constraints: Real-time systems are governed by strict, predefined TIME constraints. Processing must be guaranteed to finish within the time deadline; otherwise, catastrophic system failure occurs! قيود زمنية صارمة: محكومة بـ محددات زمنية قاطعة (Time Constraints). يجب اكتمال المعالجة قبل الموعد النهائي، وإلا حدث فشل كامل وكارثي للنظام!
  • Exam Trap Note: It is strictly time constraints, NOT memory or space constraints! تنبيه امتحاني دقيق: القيود هي قيود زمنية حتمية وليست قيوداً على المساحة أو الحجم!
📌
Past Exam True/False Trap (Real-Time Systems) فخ امتحاني خبيث مكرر (أنظمة الوقت الحقيقي) Midterm 2019 Q1.4

Midterm 2019 Q1.4: "Processing of a real-time system must be done within the predefined space constraints, or the system will fail." ➔ FALSE! It must be done within predefined TIME constraints, not space constraints!

سؤال ميدتيرم 2019: "يجب إتمام المعالجة في نظام الوقت الحقيقي ضمن قيود المساحة (space constraints) المحددة مسبقاً، وإلا سيفشل النظام." ➔ خطأ (False)! لأن الفشل يحدث عند تجاوز قيود الوقت (Time) وليس قيود المساحة!

Chapter 1 Key Terms & Exam Glossary

قاموس المصطلحات والمفاهيم المحورية للفصل الأول

Operating System
نظام التشغيل

An intermediary program between the computer user and hardware managing resources and executing user programs.

برنامج وسيط بين المستخدم وعتاد الحاسوب يدير الموارد وينفذ برامج المستخدمين بكفاءة.

Kernel
النواة

The core program running at all times on the computer, controlling hardware and critical operations.

البرنامج الجوهري الذي يعمل باستمرار على الحاسوب طوال فترة تشغيله ويدير العتاد والعمليات الحيوية.

Trap / Exception
المقاطعة البرمجية (الاستثناء)

A software-generated interrupt caused by an error (divide-by-zero) or a user system call request.

مقاطعة برمجية ناتجة عن خطأ برمجي (كالقسمة على صفر) أو طلب خدمة نظام عبر System Call.

Direct Memory Access (DMA)
النفاذ المباشر للذاكرة

High-speed data transfer directly between I/O controller buffer and RAM with only one interrupt per block.

نقل كتل البيانات مباشرة بين مخزن وحدة التحكم والذاكرة دون إشغال المعالج، بمقاطعة واحدة لكل كتلة.

Symmetric Multiprocessing (SMP)
المعالجة المتعددة المتماثلة

Multiprocessor architecture where each processor performs all tasks as peers, with no boss-worker relationship.

معمارية متعددة المعالجات تعمل فيها جميع المعالجات كأقران متساوين دون وجود رئيس ومرؤوسين.

Dual-Mode Operation
تشغيل الوضع المزدوج

Hardware mechanism using a Mode Bit to distinguish between User Mode (1) and Kernel Mode (0) for system protection.

آلية عتادية تعتمد على بت الوضع للتمييز بين وضع المستخدم (1) ووضع النواة (0) لحماية النظام.
